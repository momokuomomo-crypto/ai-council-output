- 制約：1日程度でMVP完成／Chrome拡張機能／AIを必須にしない／できるだけ多くの人が

## Stage 2: 相互レビュー

### 提案席（GPT）のレビュー

賛成：査読席の4つの批判的論点すべてに同意。
反対（事実確認込み）：
- 「組み込み決済は段階的廃止」という表現は不正確。新規有料商品は2020年9月、
  既存商品課金も2021年2月に停止しており、**実質的に既に廃止済み**
  （出典：https://developer.chrome.com/docs/webstore/cws-payments-deprecation ）
- 「販売には必ず外部決済＋ライセンス確認が必要」には反対。無料拡張＋有料Web
  サービス等、ライセンス確認なしで実現できる販売形態も複数ある
- 「販売は1日MVPの範囲外」との断定に部分的反対。「1日で販売開始」ではなく
  「1日で価値と支払意思を検証できる状態」が妥当な目標
- レッドオーシャンだから勝ち目が薄いという一般化に反対。対象を絞れば競合の
  多い領域でも参入余地はある

重複指摘：GPT5×Claude4（音声ミュート系）、GPT7×Claude2/15（フォーム系）、
GPT10×Claude8/13（会議系）、GPT9×Claude12（コピー・学習系）

追加提案：新規案を増やすより既存30案を絞り込む方針。第一候補「URLクリーン
コピー」を日本語特化にスコープ調整、第二候補「求人応募フォーム送信前チェック」
（GPT7×Claude2の再設計）、第三候補「音声タブ・コントローラー」（GPT5×Claude4統合）

未解決の論点：多くの人 vs 少人数購入のどちらを優先するか、収益モデル（買い切り/
サブスク/法人）、レッドオーシャン判定基準、MVP成功指標、公開準備の所要日数

### 査読席（Claude）のレビュー

賛成：提案席の「権限最小・バックエンドなし」方針、Vanilla JS＋MV3方針、
「ページ情報ワンクリック台帳」を有力候補とする点、段階的収益化方針

反対：
- 「リンク期限リマインダー」：ブラウザが閉じていると通知が飛ばない技術的弱点
- 「ダウンロード自動命名アシスト」：`downloads`権限は審査での説明負担・
  ユーザーの警戒感が高い。スコープ縮小を提案
- 「ページ更新差分ウォッチ」：MV3 service workerのイベント駆動・スリープ制約
  により、1日でのポーリング信頼性確保は楽観的すぎる
- 「タブ重複チェッカー」「ブックマーク受信箱」：既存の強豪（OneTab、Toby等）
  との差別化が弱い可能性

重複指摘：タブ音声管理領域（自案4×提案席5）、読書体験・可読性領域
（自案7×提案席12/13）、会議関連（自案13×提案席10）、フォーム入力補助
（自案2×提案席7）

追加提案：
- タブ音声管理と読書体験の重複領域は統合を推奨
- ダウンロード自動命名アシストは「候補提示＋ワンクリック確定」に権限縮小
- 両リストに欠けていたキーボードアクセシビリティ領域を補う新規案
  「アイデア16: リンク番号ジャンプ」を追加提案

未解決の論点：リンク期限リマインダーの通知不達対策の具体案、ダウンロード
命名アシストの権限縮小の具体設計、重複カテゴリの最終採否プロセス、
Chrome Web Store決済導線の一次情報確認の担当

## Stage 3: 統合・裁定（議長）

両席の意見はほぼ一致。Chrome Web Store決済に関する事実は、提案席がWeb検索で
確認した「既に廃止済み」を正として採用（査読席の「段階的廃止」という表現を
修正）。

**裁定：条件付き承認**
1. 一度に全部作らず、1本ずつ公開して実績を見てから次に進むこと
2. スコープ縮小の指摘がある案は、指摘どおり縮小した版から着手すること
3. 「販売」は1日目の範囲に含めず、価値検証までに留めること
4. 著作権リスクが指摘された案（字幕テキストコピー）は最優先候補にしないこと

最終アイデアリスト（29案）とおすすめ3案・最優先1案は
[稟議書_Chrome拡張機能アイデア.md](稟議書_Chrome拡張機能アイデア.md)を参照。

最優先で作るべき1案：**音声タブコントローラー**（GPT「ドメイン別ミュート記憶」
×Claude「音が出ているタブ一覧・一括ミュート」統合案）。両モデルが独立に酷似
した着想に至ったこと、権限が`tabs`のみで審査リスクが低いことを根拠とする。

## このファイルの位置づけ

**候補プールは実装キューではない。**ここに載っていることは「作ると約束した」ことを意味しない。

第3回会合で、提案席・査読席がそれぞれ独立に15案（合計30案）を提案したが、両席とも「新規案を実装キューへ積み増すべきではない」という点で一致した。理由は、実装済み・Store未提出の在庫が15本あり、公開できているのが4本のみという状態で案を足せば、第2回裁定の条件1（積み増さない）が課された後に在庫がむしろ増えたのと同じ結果になるためである。

したがって案の管理を3層に分ける（提案席の提案）。

| 層 | 内容 | 置き場所 |
|---|---|---|
| **稼働キュー** | 現在、実装または提出作業をしている案件 | [バックログ.md](バックログ.md) |
| **候補プール** | 競合調査前の案。採択数には数えない | **本ファイル** |
| **裁定済みアーカイブ** | 打ち切り・統合・今期対象外と、その理由 | 本ファイル末尾 |

運用ルール：四半期ごとに棚卸しし、根拠が更新されない案はアーカイブへ移す（候補プールの肥大化を防ぐため）。

## 番号体系について

両席が独立に「新16〜新30」と付番したため衝突が発生した。第3回裁定で**提案席案を新16〜新30、査読席案を新31〜新45**に再割当した。既存の新1〜新15（第2回会合）は変更しない。

各案の完全な原文（9項目の仕様）は、同ディレクトリの`stage1_提案席_出力.md`・`stage1_査読席_出力.md`に収録されている。本ファイルには意思決定に必要な情報を自己完結する形で記載する。

## 教訓1の分類（各案の「起動類型」欄）

- **(a) activeTabオンデマンド** — 不特定多数のドメインで、ユーザー操作時に単発実行
- **(b) optional_host_permissionsサイト単位オプトイン** — 少数の既知ドメインに常時作用
- **(c) ページ非接触** — content scriptを注入せず、Webページの内容に触れない（提出負担が最も軽い）

## 新41. 動きを止めるモード（査読席案／提案席が「特に優れている」と評価）

- **概要**：拡張アイコンを押すと、現在のページの自動再生動画の一時停止、GIF・CSSアニメーション・スクロール連動エフェクト・自動カルーセルの停止を一括で行う。`prefers-reduced-motion`を強制するCSSの注入と`video[autoplay]`の停止を組み合わせる。再度押すと解除
- **誰の困り事を解決するか**：点滅・動きで気分が悪くなる光過敏・前庭障害の当事者。動きが視界に入ると文章が読めないADHD傾向の人。会議中に共有した画面で広告が動き続けて困る人
- **なぜ需要があると思うのか**：`prefers-reduced-motion`はOS設定で有効にできるが、これを尊重しないサイトが多数を占めるのが実情で、OS設定だけでは解決しない。アクセシビリティ上の必要性が明確で審査でも説明しやすい。日本語圏で該当拡張はほぼ空白
- **Chrome API**：`activeTab`・`scripting`／**起動類型：(a)**
- **実装難易度**：低（CSS注入と`document.querySelectorAll('video,audio')`の停止が中核）／**販売難易度**：中
- **提出負担**：小。ページのスタイルを変えるが内容を読まない。「アクセシビリティ」という単一用途の説明が非常に書きやすい
- **収益化**：無料
- **将来の拡張**：サイト単位の自動適用（この段階で初めて(b)へ移行）
- **実装時間の目安**：4〜6時間
- **既存案と重複しない理由**：44案に動きの抑制を扱う案は存在しない。除外案の「20-20-20ルール休憩リマインダー」は時間管理であり表示の制御ではない。C-12・C-13は文字の読みやすさで動きは対象外
- **付された条件（提案席）**：「すべてのGIFやJavaScript製カルーセルを確実に停止できる」という表現は避けること

## 新45. 書き写しモード（査読席案／提案席が「特に優れている」と評価）

- **概要**：ページ上のテキストを選択して拡張アイコンを押すと、その文字列を画面中央に極大サイズの等幅フォントで表示する。数字は4桁ごとに区切り、英字は「B（ビー）」「D（ディー）」のように読みを併記し、`0`と`O`、`1`と`l`を色分けして区別する。表示するだけで、コピーも保存もしない
- **誰の困り事を解決するか**：予約番号・注文番号・口座番号・問い合わせ番号を電話口で読み上げる、または紙に書き写す必要がある人。画面の小さい文字が読めない高齢者。電話対応中に画面の番号を復唱する事務職
- **なぜ需要があると思うのか**：この場面ではコピーが役に立たない（相手は電話の向こう、または紙）。既存の拡大系拡張は本文全体を読みやすくする設計で、短い識別子を1文字ずつ確定させる用途に最適化されたものがない。読み間違いのコストが大きい（振込先の口座番号など）
- **Chrome API**：`activeTab`・`scripting`（または`contextMenus`＋選択テキスト受け取り）／**起動類型：(a)**
- **実装難易度**：低／**販売難易度**：中
- **提出負担**：小（保存・送信なし）
- **収益化**：無料
- **将来の拡張**：読み上げ（`tts`）による音声確認。和文の読み仮名は対象外（#23の領域と衝突するため意図的に持たない）
- **実装時間の目安**：3〜5時間
- **既存案と重複しない理由**：C-13は記事本文をReadabilityで抽出して読む「読書」用ツール。本案は短い文字列1件を確定させる「確認」用ツールで、対象の長さも使用場面も異なる。A-4・A-5はコピーが目的だが、本案はコピーしないことが要点

## 新13＋新27統合版：日付・和暦・年度変換（提案席案を既存新13へ統合／査読席が「提案席15案中の最良案」と評価）

- **Chrome API**：`contextMenus`・`activeTab`・`scripting`・Clipboard API・`storage.local`／**起動類型：(a)**（ページ非接触に近い）
- **実装難易度**：低〜中／**販売難易度**：中
- **提出負担**：低。外部通信ゼロ
- **収益化**：無料。追加書式・複数日付一括変換・基準日プリセットを買い切り候補
- **将来の拡張**：入学・卒業年度早見、年度境界の説明、曖昧日付の確認UI
- **実装時間の目安**：5〜9時間（統合分）
- **保守負債**：改元時の更新が必要だが、頻度は極めて低い
- **統合の根拠**：起動導線（右クリック）・入力（選択した日付文字列）・出力（変換結果）が3条件とも一致。査読席は「Stage 1で日付領域を『新13と近いので避ける』と判断して手放したが、避けるのではなく統合して深めるのが正解だったと認める」と自説を修正した

# 4. 今後この一覧に案を足すときの判定基準

第3回裁定で確定した、統合と打ち切りの判定基準。

## 4-1. 統合判定（3条件）

次の3条件が**すべて一致**するなら1目的であり統合する。1つでも異なるなら別拡張とする。**例外は認めない**（基準を作った当人が最初の適用で例外を作れば、その基準は以後の判断で拘束力を持たないため）。

1. **起動導線が同じ**（同じ右クリックメニュー／同じアクションボタン／同じショートカット）
2. **入力が同じ**（選択テキスト／現在URL／ローカルファイル／タブ一覧／画面キャプチャ）
3. **出力の宛先が同じ**（クリップボード／ダウンロード／画面表示／ページへの適用）

この基準の根拠：Chrome Web Storeの単一用途要件が制約するのは**目的の数であって機能の数ではない**。「選択したテキストを用途に応じた書式に整えてクリップボードへコピーする」は単一目的として説明可能であり、その中にモードが複数あることは目的が2つあることを意味しない。単一用途の説明が弱くなるのは、目的の異なるものを束ねた場合である。

## 4-2. ノックアウト・ゲート（第1段・二値判定）

配点の前に、該当するものを落とす。

- **G1（重複）**：既に公開済み、または他の未提出案と、起動導線・入力・出力の宛先が3つとも一致する → **統合へ**
- **G2（外部依存が塞がっている）**：外部API・外部設定・対象サイトの許諾に依存し、その依存が現時点で解消されていない → **打ち切り**
- **G3（未使用）**：作者本人が直近1か月で一度も使っていない → **打ち切り候補**（1件でも該当したら理由の記述を義務づける）
- **G4（重大な法務・機微データリスク）**：健康・金融・認証情報・入力内容の保存に関わる → **打ち切りまたは要件の追加**

**G3が要点である。**これが唯一、自己採点バイアスを受けない事実判定であり、これがなければ打ち切りは実質的に発動しない。判定は作者本人にしかできず、AIには代行できない。

## 4-3. 配点（第2段・順序付け専用）

ゲートを通過したものを並べるためだけに使う。**採否の判定には使わない。**

| 評価軸 | 配点 |
|---|---:|
| 単一用途を一文で説明できる | 16 |
| 権限が少なく説明しやすい | 16 |
| 手動試験で主要動作を再現できる | 16 |
| 対応サイト変更への依存が少ない（**下限5点**） | 10 |
| プライバシー開示が単純 | 10 |
| スクリーンショット3枚以内で価値を説明できる | 11 |
| 類似拡張との差別化 | 11 |
| 維持管理が月1時間以内（**下限5点**） | 10 |

（提案席の原案から法務5点をG4のゲートへ移し、残り95点を100点に按分した。「対応サイト変更への依存」と「維持管理」に補償不可の下限を設けたのは、これらが他の長所で埋め合わされてはならない性質の軸だからである。下限を割ったら合計点に関係なく保留。）

**絶対閾値（75点／60点）は使わない。**配点が変われば意味が変わり、十数本しかないものに絶対閾値を当てる実益がない。代わりに「その期に出す本数を先に決め、上位から順に出す」という相対運用にする。

## 4-4. 選別軸から外すもの

**実装時間の目安を、案の採否・優先順位の根拠として使わない。**

第3回会合で、19本が約3.5日で「実装済み」になっていることが記録から確定した（1日5.4本）。これは労働時間では説明できず、ai-build-councilによる並列実行が最も自然な説明である。**この体制下では実装時間は律速ではなく、44案の「実装時間の目安」欄は意思決定の材料として機能していない。**

代わりに選別軸とするのは、**本数に比例して人間の直列作業に返ってくる3要素**である。

1. **保守負債** — Chromeの破壊的変更・対象サイトのDOM変化・問い合わせ対応。公開した瞬間に発生し、並列化できない
2. **提出負担** — 権限説明・プライバシー開示・スクリーンショットの訴求判断・Dashboard操作・審査応答
3. **ポリシーリスク** — スパム／重複コンテンツ判定は本数と類似度に比例し、制裁はアカウント単位で全拡張に及ぶ

**実装コストが下がったことは、この3つを1円も下げない。むしろ実装が安いことは選別の重要性を高める。**選別が働かなければ、安いという理由だけで在庫が無制限に増え、そのすべてが保守負債とポリシーリスクの候補になる。

## 4-5. 外部API依存に関する一般ルール

外部APIの**認証情報（トークン・APIキー）を必要とする案は、原則としてシリーズの対象外**とする。理由は3つ。(i) 配布物に同梱すれば秘密が保持できず規約に抵触しうる、(ii) サーバー側に置けば運用コストが1日MVPの前提と両立しない、(iii) ユーザー数が増えるほど1つの認証情報にリクエストが集約され、成功が制約に当たる。

**例外**：認証情報を必要としない公開エンドポイント（認証なしで誰でも叩ける）であり、かつユーザー1人あたりのリクエスト頻度が十分低い場合は対象内とする。

F-21は、この原則が第1回で明文化されていれば設計に着手する前に落とせていた案である。

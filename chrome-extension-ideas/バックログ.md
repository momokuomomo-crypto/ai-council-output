## 完了の定義とWIP上限（第3回裁定7-5）

**完了 = Chrome Web Storeで公開完了。** 実装完了・提出準備完了は成功指標として0点で数える。ただし工程管理のために中間状態は残す（どこで滞留したかを測るため）。

**工程状態**：未着手 → 設計中 → 実装中 → 実装済み（監査待ち） → 開発完了（提出可能） → 出荷完了（提出済み） → 審査中 → **公開完了**
そのほか：今期対象外／打ち切り

**WIP上限（超えたら新規実装を停止する。目標ではなく制約）**

- 未提出在庫（実装済み〜出荷完了の合計）：**5件以下**
- Store提出準備中：同時**2件**まで
- 新規実装中：同時**1件**まで
- 同時に審査中：**3件**まで
- 提出ペース：**週2本**まで（根拠は工数ではなくスパム／重複コンテンツ判定リスクと審査キュー）
- 滞留期限：開発完了から出荷完了まで**7日**を超えたらトリアージへ差し戻す

**主指標**：公開完了の本数。**ガードレール**：審査却下ゼロ／ポリシー警告ゼロ／同時審査3件以下。

## 運用ルール

### 案を追加するとき

- **新しいアイデアは、このファイルではなく[候補プール](候補プール_Chrome拡張アイデア.md)に追加する。**稼働キューへ移すのは、競合調査とStore掲載文の作成を通過したものだけ
- 稼働キューへ移す前に、ノックアウト・ゲート4項目（G1重複／G2外部依存が塞がっている／G3作者本人が直近1か月で未使用／G4重大な法務・機微データリスク）を通す
- **統合判定**：起動導線・入力・出力の宛先の3条件がすべて一致するなら統合、1つでも異なるなら分離。例外は認めない

### 案を選ぶとき

- **実装時間の目安を選別軸に使わない。**19本が約3.5日で実装済みになった実績から、この体制では実装時間は律速ではない
- 代わりに**保守負債・提出負担・ポリシーリスク**（いずれも本数に比例して人間の直列作業に返ってくる）で選ぶ
- **外部APIの認証情報を必要とする案は原則対象外**。例外は認証不要の公開エンドポイントかつリクエスト頻度が十分低い場合

### 状態を更新するとき

- 実装が終わっても「実装済み（監査待ち）」まで。**提出可能かどうかは監査で決まる**（クリーン環境でビルドできるか／主要機能が仕様どおり動くか／SW再起動・権限取消・非対応ページを処理できるか／リモートコードや不要権限がないか／掲載素材を作成できるか）
- 監査でA級（2時間以内で提出可能）／B級（2〜8時間の仕上げ）／C級（8時間超・再設計・仕様未確定）に分類し、C級が多ければPhase 1の目標本数を下方修正する
- 打ち切ったものは行を削除せず、上の「打ち切り・不採用」表へ理由と判定日つきで移す

# 稟議書：Chrome拡張機能アイデア（1日MVP・継続公開シリーズ）

## テーマ

Chrome拡張機能を継続的に開発し、Chrome Web Storeへ公開しながら経験を積む。
最初から大規模なものは作らず、1日程度で完成できる小さな拡張機能を作る。

## 検討体制

| 席 | 担当 | モデル |
|---|---|---|
| 議長 | 統合・裁定 | Claude Fable（Claude Code本体セッション） |
| 提案 | 実現案・具体策 | GPT（Codex CLI, gpt-5.6-sol） |
| 査読 | 批判的検証 | Claude（Agentサブエージェント） |

## 条件

1日程度でMVPが完成／Chrome拡張機能／AI必須にしない／できるだけ多くの人が使える／
人の困り事を解決する／公開・販売まで考慮／継続的にアップデートできる／
既存ライブラリ・既存サービスを積極的に利用する／車輪の再発明はしない。

## 論点整理

- 目的：アイデアを最低20案、指定フォーマットで提案すること
- 判定基準：実現可能性（1日で作れるか）・需要の現実性・差別化・収益化の実現性
- 実行計画：提案(GPT)・査読(Claude)が独立に15案ずつ考案→相互レビュー（重複整理・
  実現性チェック）→議長が統合し最終29案＋おすすめ3案＋最優先1案を裁定

## 合意点

- 1日で作れるのは「ローカルで動くMVP」まで。Chrome Web Store公開には審査・
  プライバシーポリシー・単一目的の説明などの準備が別途必要
- 単一目的・最小権限の設計が公開のしやすさに直結する
- 「幅広い需要」と「差別化（車輪の再発明回避）」は本質的にトレードオフがあるが、
  対象を絞る（日本語・特定職種・プライバシー重視等）ことで両立の余地がある
- 30案近くを同時に公開するのではなく、1本ずつ作り、実績を見てから次に進むべき
- 収益化は無料版での需要検証を先に行い、外部決済は後から追加する段階的アプローチが妥当

## 相違点・修正した論点

- **Chrome Web Storeの組み込み決済について**：査読席は当初「段階的廃止」と表現したが、
  提案席がWeb検索で確認した事実として、新規有料商品の作成は2020年9月、既存商品の
  課金も2021年2月に停止しており、**実質的に既に廃止済み**。この稟議書では正しい方を採用する
- **「販売は1日MVPの範囲外」への反論**：提案席は「本番の自動課金・ライセンス管理は
  範囲外だが、無料MVP＋価格表示＋購入希望フォームまでの『支払意思の検証』は1日に
  含められる」と反論。この見解を採用し、目標は「1日で販売開始」ではなく
  「1日で価値と支払意思を検証できる状態」とする

## リスク

- 権限の広い案（ダウンロード命名、個人情報検出系）は審査での説明負担・ユーザーの
  警戒感が高い → 該当案はスコープを縮小して提示（本文参照）
- 著作権に触れる可能性のある案（字幕テキストコピー）は審査却下リスクが高く、
  優先度を最も低くする
- レッドオーシャン領域（サイトブロック等）は差別化なしでは埋没するリスクが高い

## 裁定：条件付き承認

以下の条件で、本アイデア群を「作る価値がありそうな候補」として承認する。

1. 一度に全部作らず、1本ずつ公開して実績を見てから次に進むこと
2. スコープ縮小の指摘がある案（ダウンロード自動命名アシスト、画像ぼかしチェッカー、
   フォーム個人情報混入警告）は、指摘どおり縮小した版から着手すること
3. 「販売」は1日目の範囲に含めず、価値検証までに留めること
4. 著作権リスクが指摘された案（字幕テキストコピー）は最優先候補にしないこと

## 最終アイデアリスト（29案）

全29案の詳細（タイトル・概要・困り事・需要根拠・Chrome API・実装難易度・
販売難易度・収益化方法・将来の拡張案・実装時間）は、本会合のチャット出力を参照。
`_history/`に将来のバージョンが追加された場合、このファイルは最新版に更新される。

### 最もおすすめの3案

1. **ページ情報ワンクリック台帳** — 両席独立に高評価。`activeTab`のみで完結し
   審査が通りやすく、既存ライブラリ（Papa Parse）活用で車輪の再発明も回避
2. **音声タブコントローラー**（ドメイン別ミュート記憶＋音声タブ一覧・一括ミュートを統合）
   — GPT・Claudeが互いを見ずに独立に酷似案を提案＝需要の実在性を裏付ける強いシグナル
3. **URLクリーンコピー（日本語SNS・EC・求人サイト特化版）** — 実装時間最短クラス。
   対象を絞ることで差別化可能という条件付き

### すぐ作るべき1案

**音声タブコントローラー**を最優先で推奨する。

理由：(1) 両モデルが独立に酷似した着想に至った＝アイデアの筋の良さについて
最も強い合議的根拠がある、(2) 権限が`tabs`のみで個人情報・ページ内容への
アクセスが不要＝審査の単一目的・最小権限ポリシーに最も適合し差し戻しリスクが
低い、(3) 外部ライブラリ・バックエンド・ログイン不要で「初めて公開まで一周する」
練習台として最も安全、(4) 実装時間5〜7時間で1日で完結する規模。
